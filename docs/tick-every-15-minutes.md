# Плановая проверка каждые 15 минут

Плановая проверка (`/api/cron/tick`) повторяет упавшие и зависшие сообщения Telegram, напоминает о необработанных заявках и повторяет недоставленные карточки. Сейчас она запускается:

- каждый день в 09:00 по Москве (крон Vercel, на бесплатном тарифе чаще нельзя);
- после каждого сообщения в ИИ-консультанта и каждого действия в админ-боте, при каждой новой заявке и открытии админки, но не чаще раза в 4 минуты.

Чтобы она шла строго каждые 15 минут, есть два пути.

## Вариант 1. GitHub Actions (бесплатно)

Файл сценария готов: `.github/workflows/tick.yml` (текст ниже). Секреты в репозитории не нужны: GitHub подписывает каждый запуск, сайт проверяет подпись и то, что запуск пришёл из репозитория `ivantemshik/stroy` и из файла `tick.yml`. Другой репозиторий или другой файл получит отказ.

Расписание в GitHub работает только из ветки по умолчанию (`main`), поэтому файл нужно положить в `main`. Сделать это может:

- владелец репозитория в браузере: GitHub, репозиторий, «Add file», «Create new file», имя `.github/workflows/tick.yml`, вставить текст ниже, «Commit changes» в `main`;
- или разработчик с токеном GitHub, у которого есть право `workflow`: `gh auth refresh -h github.com -s workflow`, затем отправить файл в `main`.

Проверка после добавления: вкладка «Actions», сценарий «Плановая проверка сайта», «Run workflow». Шаг должен завершиться зелёным, в логе ответ сайта: итог проверки в JSON или `{"skipped":"недавно запускался"}`, если проверка уже шла в последние 4 минуты. Отказ `401` значит, что файл лежит не в том репозитории или не под тем именем.

```yaml
name: Плановая проверка сайта

on:
  schedule:
    - cron: '*/15 * * * *'
  workflow_dispatch:

permissions:
  id-token: write
  contents: read

jobs:
  tick:
    runs-on: ubuntu-latest
    timeout-minutes: 2
    steps:
      - name: Запустить плановую проверку
        run: |
          TOKEN=$(curl -fsS -H "Authorization: bearer $ACTIONS_ID_TOKEN_REQUEST_TOKEN" "$ACTIONS_ID_TOKEN_REQUEST_URL&audience=dom-mira-tick" | jq -r .value)
          curl -fsS -m 60 -X POST -H "Authorization: Bearer $TOKEN" "${{ vars.SITE_URL || 'https://dom-mira.vercel.app' }}/api/cron/tick"
```

Если репозиторий переедет, на хостинге задаётся переменная `GITHUB_TICK_REPO` с новым именем (`владелец/репозиторий`).

## Вариант 2. Тариф Vercel Pro

Для коммерческого сайта Pro всё равно нужен до запуска. На нём в `vercel.json` в раздел `crons` добавляется строка `{"path": "/api/cron/tick", "schedule": "*/15 * * * *"}`, и GitHub Actions не нужен.
